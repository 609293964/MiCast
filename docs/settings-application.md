# 设置如何生效

本文描述设置从“已保存”到“实际声音已改变”的完整范围。这里的 AirPlay 1
指经典 AirPlay/RAOP 实时接收，AirPlay 2 指原生 AirPlay 2 接收；DLNA 指手机把
媒体地址交给 MiCast 的 DLNA 接收入口。

## 生效方式

MiCast 的设置分为四类：

1. **实时读取**：后续音频块直接读取新值，不重启编码器。例如小米音箱的组合延迟。
2. **编码器热重建**：保留手机会话和音箱 HTTP 端点，只重建受影响的编码器。EQ、夜间模式、
   响度补偿、组合响度和编码参数属于这一类。EQ 编辑在网页端等待 300 ms、后端再合并
   600 ms 内的连续更新；接口只有在最终配置已应用后才返回，页面显示“EQ 已应用”。
3. **局部管线重建并重新投放**：声道、成员、播放目标或流格式发生结构变化时，只重建受影响
   的入口，并让正在播放的音箱重新拉取正确地址。
4. **下次会话或应用重启**：音量控制方式在新会话开始时锁定；管理端口需要重启应用才能换绑。

设置应用失败时，运行计划不会再被标记为成功；相同设置仍可重试。保存值与实际运行值不再因
一次编码器失败而永久漂移。

## 多端编辑与撤销

- 每台音箱的调音状态带有持久化版本号。网页提交曲线、夜间模式、响度补偿、场景切换、导入
  或校准结果时，必须基于自己最后读取的版本。
- WebSocket 会广播版本变化；调音页同时以 2.5 秒轻量检查兜底。另一台设备修改后，当前页面
  自动载入完整曲线和预设状态。
- 两端同时写入时，旧版本不会静默覆盖新版本；旧端会收到冲突提示并载入服务端最新状态。
- 每次会改变声音的单音箱调音操作都会在服务端保存一个快照。“撤销上一次调整”可跨页面、
  跨设备以及重新打开应用使用；撤销成功后快照被消费，不提供无限历史或重做。
- 系统预设名称由服务端持久化。重新进入页面时优先使用明确的预设标识，而不是仅凭浮点曲线
  猜测，因此 Harman 等预设不会再错误显示为“自定义”。

## 按协议区分

| 设置 | AirPlay 1 | AirPlay 2 | DLNA 输入 |
|---|---|---|---|
| MP3/FLAC/WAV、码率、采样率、自动转码 | 当前会话热重建编码器；格式变化后音箱重新拉流 | 当前会话热重建编码器，不重启 AirPlay 2 接收进程；格式变化后音箱重新拉流 | 不使用这组实时管线参数。独立音量模式使用固定 MP3 192k/44.1 kHz 代理；联动模式把原媒体地址直接交给音箱 |
| 每音箱 EQ、预设、夜间模式 | 当前会话生效；连续编辑合并为最终一次编码器重建 | 与 AirPlay 1 相同 | 当前不支持；DLNA 媒体绕过实时 PCM/EQ 管线 |
| 等响度补偿 | 当前会话生效；跨响度档位时重建编码器 | 与 AirPlay 1 相同 | 当前不支持 |
| 组合响度（dB） | 当前会话热重建受影响编码器 | 与 AirPlay 1 相同 | 当前不支持 |
| 左右声道 | 局部重建入口并让音箱重新拉取左右流 | 局部重建对应 AirPlay 2 实例并重新投放 | 当前 DLNA 输入不拆分左右声道 |
| 小米音箱组合延迟 | 后续流数据实时读取；不重启编码器 | 与 AirPlay 1 相同 | 当前 DLNA 输入不经过延迟缓冲 |
| 局域网 AirPlay 目标延迟/声道 | 重新连接受影响的网络目标 | 与 AirPlay 1 相同 | 不适用 |
| 局域网 DLNA 目标声道/成员 | 重新向受影响的渲染器投放当前 AirPlay 音频 | 与 AirPlay 1 相同 | DLNA 输入目前不转发到这条实时输出链路 |
| 独立音量/音量联动 | 下次 AirPlay 会话生效，当前会话保持原模式 | 下次 AirPlay 2 会话生效 | 下次设置媒体地址时生效，当前媒体保持原模式 |
| 起播音量 | 下次会话开始时应用；联动模式不覆盖发送端音量 | 与 AirPlay 1 相同 | 下次播放开始时应用；仅独立模式 |
| 音箱物理音量/静音 | 立即向指定音箱发送命令 | 与 AirPlay 1 相同 | 与输入协议无关，立即发送 |

## 其他设置

- 新增、删除、启停或重命名经典 AirPlay 入口：局部更新发现服务和对应管线；其他入口保持播放。
- AirPlay 2 实例的目标、名称、成员或声道变化：只重建受影响实例；其他实例保持播放。
- 开关 AirPlay 2 或切换接收协议/接收器模式：需要重建相关接收服务，会造成短暂中断。
- DLNA 开关：立即重新发布或撤销 DLNA 发现服务。
- 音频流端口：立即重新绑定；端口冲突时自动寻找后续空闲端口。管理页面端口需重启应用。
- AirPlay RTSP/UDP、AirPlay 2 端口：重启相关音频服务后生效。
- 名称、登录通知、歌词匹配、发现开关等控制设置不改变已经编码的声音；各自按页面提示立即或
  下次会话生效。

## 已知边界

DLNA 输入目前是“把媒体地址直接交给音箱”或“通过固定 MP3 代理提供独立音量”，不是先解码
成共享 PCM 再进入 AirPlay 使用的实时处理管线。因此不能承诺 EQ、组合延迟、声道拆分和用户
选择的编码参数对 DLNA 输入生效。若以后要统一这些能力，应把 DLNA 输入接入同一 PCM 管线，
而不是在界面层假装设置已经应用。
